## 程序架构

### 执行流程

```text
main()
  │
  ├─ install_console_guard() 注册控制台事件回调（用于 Ctrl+C 场景）
  │
  ├─ 读取用户输入（逗号分隔多个路径 / URL）
  │
  ├─ 对每个输入调用 process_input()
  │     │
  │     ├─ is_url() 判断是 URL 还是本地路径
  │     │
  │     ├─ [URL] download_image() → 临时文件 → decode_qrcode() → 清理临时文件
  │     │
  │     └─ [本地] decode_qrcode()
  │
  └─ keep_console_open() 双击启动时把窗口交给 PowerShell
```

### 解码核心 decode_qrcode

```text
decode_qrcode(image_path)
  │
  ├─ image::open() 加载图片
  │
  ├─ preprocess_image() 生成 10 种预处理图像（首项即原图）
  │     └─ 逐一调用 decode_qr_image()，首个命中即输出并返回
  │
  ├─ [全部失败] log_warning → 裁剪图像四角重试
  │     └─ 逐一调用 decode_qr_image()，首个命中即输出并返回
  │
  └─ [仍失败] log_error + 用户建议
```

## 使用方法

程序启动后提示输入一行文本，输入项以英文逗号分隔：

```text
请输入二维码图片的路径或 URL（多个用逗号分隔）:
```

| 场景 | 输入示例 |
|------|----------|
| 单个本地图片 | `C:\path\to\qrcode.png` |
| 多个本地图片 | `C:\path\to\qrcode1.png, C:\path\to\qrcode2.jpg` |
| 网络图片 | `https://example.com/qrcode.png` |
| 带签名参数的 CDN URL | `https://s3.amazonaws.com/bucket/key.png?X-Amz-Signature=abc&X-Amz-Expires=3600` |
| 本地与网络混合 | `C:\path\to\local.png, https://example.com/remote.jpg` |

## 技术说明

### URL 识别规则

判定函数 `is_url()` 使用如下正则，大小写不敏感：

```regex
(?i)^https?://\S+\.(png|jpg|jpeg|gif|bmp|webp)(\?\S*)?(#\S*)?$
```

支持的场景：

| 场景 | 示例 |
|------|------|
| 普通图片 URL | `https://example.com/qr.png` |
| 大写扩展名 | `https://example.com/QR.PNG` |
| 带端口 | `https://example.com:8080/qr.png` |
| 带查询参数 | `https://example.com/qr.png?token=abc` |
| 带页内锚点 | `https://example.com/qr.png#top` |
| 多级路径 | `https://cdn.example.com/a/b/c.png` |

### 图像预处理流程

预处理函数 `preprocess_image()` 按以下顺序生成 10 个候选图像，逐一送入解码器：

| # | 名称 | 方法说明 |
|---|------|----------|
| 1 | 原始图像 | 直接 clone 输入图像，作为第一个尝试入口 |
| 2 | 灰度图像 | `to_luma8()` 转灰度 |
| 3 | 高对比度图像 | 在灰度基础上 `contrast(2.0)` |
| 4 | 二值化图像 | 对高对比度图做阈值 128 二值化 |
| 5 | 二值化图像（阈值 64） | 对高对比度图做阈值 64 二值化 |
| 6 | 二值化图像（阈值 192） | 对高对比度图做阈值 192 二值化 |
| 7 | 高斯模糊+二值化 | 灰度图 `blur(1.0)` 后阈值 128 二值化 |
| 8 | 锐化图像 | 原图 `to_rgba8()` 后 `unsharpen(1.0, 0)` |
| 9 | 颜色反转图像 | 灰度图每像素 `255 - v` |
| 10 | 放大图像 | 原图 2× 放大（Lanczos3 算法） |

### 裁剪策略

若所有预处理变体均解码失败，程序输出 WARNING 日志，并对图像四角分别裁剪为 1/4 大小重试：

| 区域 | 裁剪坐标 (x, y, x2, y2) |
|------|------------------------|
| 左上角 | (0, 0, width/2, height/2) |
| 右上角 | (width/2, 0, width, height/2) |
| 左下角 | (0, height/2, width/2, height) |
| 右下角 | (width/2, height/2, width, height) |

每个裁剪区域独立传入 `decode_qr_image()`，命中即输出并终止。

### 错误日志设计

`download_image()` 对每个可能失败的网络 / IO 步骤单独 `match` 并输出 `log_error`，失败原因可直接定位：

| 步骤 | 错误消息 |
|------|----------|
| HTTP 客户端构建 | `创建 HTTP 客户端失败: {错误详情}` |
| 发送请求 | `网络请求失败: {错误详情}` |
| 响应状态非 2xx | `HTTP 错误: {状态码}` |
| 读取响应体 | `读取响应体失败: {错误详情}` |
| 创建临时文件 | `创建临时文件失败: {错误详情}` |
| 写入临时文件 | `写入临时文件失败: {错误详情}` |

`Content-Type` 不以 `image/` 开头时输出 WARNING 但不阻断流程，由后续 `image::open` 决定能否解码。

### 日志格式

所有日志遵循统一格式：

```text
{YYYY-MM-DD HH:MM:SS} - {级别} - {消息}
```

| 级别 | 颜色 | 输出流 |
|------|------|--------|
| INFO | 蓝色 | stdout |
| WARNING | 黄色 | stdout |
| ERROR | 红色 | stderr |

### 启动方式与设计前提

本工具从设计之初只面向一种启动方式：**在终端里 cd 到 exe 所在目录、输入 exe 全名回车**。作者原话是"没有考虑到有人会用双击的方式启动这个小工具"。

因此程序**不解析命令行参数**（`Cargo.toml` 无 `clap` / `getopts`，代码中无 `std::env::args()`），唯一的输入通道是标准输入的一行文本。由此带来两个已知行为：

| 启动方式 | 行为 |
|----------|------|
| 终端内运行 / `cargo run` | 正常，输入提示符等待一行文本 |
| 拖图片到 exe 上、`QRCodeScanner.exe xxx.png` | 参数被操作系统丢弃，程序仍停在输入提示符 |

若将来要支持拖拽，需读取 `std::env::args()`，并在无参数时保留现有交互提示。

### 控制台窗口保留

双击启动时，进程一退出，Windows 会立刻销毁它独占的控制台窗口，解码结果随之消失。`keep_console_open()` 用于消除这一闪退。

#### 生效判定

`owns_console_alone()` 调用 Win32 `GetConsoleProcessList`，仅当返回值为 1（控制台内只有本进程）时才动作。实测三种启动方式：

| 启动方式 | 控制台进程数 | 是否派生 shell |
|----------|--------------|----------------|
| 新建控制台（等价双击） | 1 | 是 |
| 复用宿主终端（`-NoNewWindow`） | 4 | 否 |
| Git Bash 直接运行 | 3 | 否 |

该门控保证守卫只服务双击场景，不会在开发和终端使用时凭空塞进一层嵌套 shell。

#### 保留机制

在当前控制台内 `spawn` 一个交互式 PowerShell，携带 `-NoExit` 与 `CREATE_NEW_PROCESS_GROUP`：

- 新 shell 与本进程共享同一控制台，本进程退出后控制台因仍有存活进程而保留；
- `CREATE_NEW_PROCESS_GROUP` 使新 shell 不被发给本进程的 Ctrl+C 广播波及。

#### Shell 选择

优先使用 PATH 中的 `pwsh`（PowerShell 7），派生失败则回退到 Windows PowerShell 5.1，其位置由绝对路径确定：

```text
%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe
```

5.1 走绝对路径是因为它不在 `System32` 根目录下，避免用户修改 PATH 后查找失败。

#### 退出路径覆盖

| 退出路径 | 是否保留窗口 |
|----------|--------------|
| 正常解码结束 | 是 |
| 空输入 / 无有效路径 → `exit(1)` | 是 |
| Ctrl+C 强制终止 | 是（经 `SetConsoleCtrlHandler` 回调） |
| panic（如 `read_line` 的 `expect` 失败） | 否 |
| 点击窗口关闭按钮 | 否（控制台本身正在销毁） |

## 注意事项

### 使用相关

- 确保二维码图像清晰完整，模糊或严重遮挡可能导致失败
- 支持 PNG、JPG、JPEG、GIF、BMP、WEBP，扩展名大小写不敏感
- URL 图片需要网络连接，超时设置为 30 秒
- 临时文件在解码流程结束后自动清理，无需手动管理
- 批量输入以英文逗号为分隔符，路径本身不能包含逗号

### 启动相关

- 不解析命令行参数，拖图片到 exe 上不会触发解码，详见[启动方式与设计前提](#启动方式与设计前提)
- 双击 exe 启动时，程序结束后窗口由 PowerShell 接管，不会闪退；PowerShell 冷启动约需 0.5–1.5 秒，窗口会先空一下再出现提示符
- 在已有终端里运行或 `cargo run` 时上述守卫不生效，行为与加入该功能之前完全一致
